Getting started with Hephestus 2.0

FULL, EXPLICIT AUTHORIZATION IS REQUIRED before launching or using Hephestus against any system. Use only within an agreed scope on systems you own or have permission to assess.

A supervised local model proposes commands. You review each command before execution. Choose where commands run using Local / Remote in Workspace.

From master's research to public release

Hephestus began as Daryl Gatt's MSc in Cyber Security artifact at the University of Wolverhampton. The 2026 dissertation, Chains of Command: How Agentic AI Alters Attacker Tactics, Techniques and Procedures, evaluated an earlier, less capable research beta. It was then substantially upgraded into V1 for the author's red-team work and developed further into this public V2.

The master's study did not evaluate V1 or V2. The beta produced useful Linux enumeration and partial Windows findings, but its retained outputs did not verify the protected-file or privileged-shell goals. The study informs the project's focus on approvals and inspectable output; it provides no performance benchmark or safety validation for this release. See README and docs/RESEARCH-BACKGROUND.md for methods, findings and sources.

1. Load a model

Start with a coding-focused Instruct/Chat model in a single, complete .gguf file. Coding models are a useful starting point for scripts; general-purpose Instruct models can also work. No model guarantees correct commands. Prefer Instruct/Chat over a Base-only model and always review proposals.

Easiest download: from the project folder run python setup.py --model-only --download-model after installation, or python setup.py --download-model to install dependencies too. This gets the pinned official qwen2.5-coder-1.5b-instruct-q4_k_m.gguf (about 1.12 GB), verifies its size/header/SHA-256 and saves it in models/.

Manual download: visit the official model files on Hugging Face, open Files and versions and download exactly qwen2.5-coder-1.5b-instruct-q4_k_m.gguf using the file download control. Or search Hugging Face Models for Coder Instruct GGUF. Read the publisher's model card, license, runtime requirements and checksums. Manual downloads do not automatically receive setup's pinned verification.

Download one complete quantization, not every file. Q4_K_M is a practical starting compression; Q5/Q8 variants need more memory. For this workflow avoid split shards, LoRA adapters, embedding models and mmproj files. .safetensors, PyTorch .bin, GPTQ, AWQ and EXL2 cannot load directly here. A compatible self-contained GGUF normally needs no separate tokenizer/config download, Ollama installation or cloud API key.

  1. Finish the download and move the actual complete .gguf into the application's models/ folder. Do not use a ZIP, partial download or saved web page.
  2. Open Models → Rescan, choose the Load control, and wait for Loaded. Nothing loads automatically at startup.
  3. Try “Print a greeting” in Local mode and inspect the command before approving. Stop a task and eject before switching models.

Source checkouts use the project's models folder; installed packages use the per-user application data folder, configurable with HEPHESTUS_DATA_DIR (see README). The Models screen scans files; it does not download from Hugging Face. A GGUF extension alone does not guarantee that its architecture or chat template works with this runtime.

CPU is supported. GPU offload requires a compatible inference wheel and drivers; choose the backend during setup. Memory use exceeds model file size and grows with context. Start small; if memory runs out, lower context/batch size, reduce GPU layers or use a smaller model. Garbled output can indicate an incompatible chat template.

2. Work on this computer

Local is selected on every launch. No worker, relay, keys or tunnel are needed. Enter an authorized objective and scope in Workspace. Quick performs a small task; Goal iterates toward an objective. Review the complete proposal in the browser: approve selected, reject, update guidance, or abort. Commands run with your account's permissions.

Try a harmless task such as “Print a greeting”. Stop ends the task; it keeps your model loaded. A dry run configured in YAML records proposals without executing them.

3. Work on another Windows computer

The model and browser stay on this controller. Only approved commands execute on the remote computer. Install the optional cloudflared executable on the controller first (see README). The target needs Windows PowerShell 5.1 or later and outbound HTTPS access; it needs no Python or model.

The relay runs temporarily in memory on your controller. cloudflared gives it a temporary HTTPS trycloudflare.com address through Cloudflare's network; Cloudflare does not host your model or Hephestus relay. The target's remote_handler.ps1 makes outbound HTTPS requests to fetch jobs and return encrypted results. Only the relay is exposed; your browser UI stays on loopback. Cloudflare carries traffic and may observe connection metadata.

  1. Stop any active task and select Remote in Workspace. Allow up to 25 seconds for the temporary tunnel.
  2. Download the private connection ZIP below. Transfer it securely to the authorized target and extract all files into one private folder.
  3. On the target run .\Connect-Hephestus.ps1 in PowerShell, or open that script in PowerShell ISE and press F5. Follow the target's script execution policy. Keep the script running.
  4. Wait for “Remote worker connected” on this controller, then start a task. The target operator reviews every full script: Y approves, N rejects, U requests an edit, Q quits.
  5. When finished, stop the task and select Local. This closes the tunnel and destroys the controller's temporary keys. Delete the downloaded ZIP and extracted folder from both computers.

Select Remote in Workspace to prepare a connection.

If you change the command timeout or output limit in Settings, download a new bundle and relaunch the worker before starting another task. The bundle grants access to this remote session. Never upload it to GitHub. Every new connection needs a new bundle. Stop & disconnect cancels the task and current worker; restart the worker script to reconnect while the same remote session is open. Returning to Local or closing the server ends that session.

4. Review evidence and export

Session history stores local command proposals, decisions, output and events. Ask the AI can explain selected evidence while no task is running. Export JSON for machine-readable evidence or PDF for a generic cybersecurity audit report, including SHA-256 integrity hashes. Hashes detect changes to exported evidence; they do not prove that a goal succeeded or independently authenticate the report.

Reports contain your supplied scope and captured output. Review them before sharing. Delete sessions in the sidebar when no longer needed.

Troubleshooting

  • No model: add a compatible GGUF to models/, refresh and load it.
  • Cannot select a mode: stop the active task and wait for it to finish stopping.
  • No cloudflared: install it on the controller and restart the app. Local remains available.
  • Worker offline: run the extracted launcher, check outbound HTTPS and synchronize both clocks. If the tunnel ended, select Local then Remote and transfer a fresh bundle.
  • Script blocked: follow your administrator's approved execution/signing policy. ISE is optional.
  • Permission denied: commands use the target account's rights. No automatic elevation is provided.
  • Private UI access: open the complete capability URL printed by the launcher. Keep it private and do not expose port 5000.
